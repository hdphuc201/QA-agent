## Implementation summary

- **T01** `src/generator/{codegen,generate}.ts` + `qa-agent generate`: only READY cases (validated plan) → one spec per feature with deterministic names (`approval.spec.ts`, …). Tests are titled `<caseId> <title>`, tagged `@P0 @rbac @<requirement>` and annotated with the case and requirement IDs; `case-map.json` maps case ID → file/test.
- **T02** Locators are `getByRole` / `getByLabel` / `getByText` with exact names only. No CSS/XPath (asserted for every case).
- **T03** Assertions map 1:1 from the plan's structured assertions (asserted): URL path, heading, text (scoped to the table row of the created record when one exists), alert, absent element (RBAC UI), HTTP status through the role's own context (401/403/400), item count unchanged via the list API (persistence). Each expectation is a `test.step` quoting the requirement line.
- **T04** Runtime `src/generator/runtime/qa-agent.fixtures.ts` (a real, type-checked file copied with the project config): one BrowserContext per role (isolated cookies) with teardown in `finally`, extra tabs per role, login through the recipe, credentials only from `QA_AGENT_ACCOUNT_*` (missing → `QA_AGENT_BLOCKED`), unique traceable data (`QA <key> <caseId> <run>-w<worker>-<n>`), subject capture, `apiCount`. Data lifecycle: `testData.resetPath` → generated globalSetup/Teardown. It is refused on production and when the base URL origin is not allowlisted.
- **T05** `src/generator/validate.ts`: strict `tsc` over the generated files plus `playwright test --list` using the **target's** `@playwright/test`, counting only generated case IDs; BLOCKED when Playwright is absent. Output is formatted with fixed Prettier options; golden files are in `tests/golden/sample-app/`.
- **T06** Idempotency through `.qa-agent-manifest.json` (hashes): unchanged files are not rewritten; edited or foreign files are never overwritten (`*.qa-agent-new`); unmodified stale files are removed, edited ones kept. Writes go through the write guard.
- The `generate` skill calls the engine; `scripts/smoke/run-sample-suite.mjs` runs the generated suite against a fresh sample app; `scripts/quality-gate.mjs` runs the whole gate with one log per check.
- Policy change (owner request): each passed phase is now committed **and pushed** to `origin/main` (ADR 0003 addendum). P0–P3 were pushed during this phase.

## Test evidence (gate criteria)

- **Spec compiles; `--list` sees the cases:** `tests/integration/generate.test.ts` checks strict tsc OK and 19/19 listed, plus BLOCKED when `@playwright/test` is missing.
- **Stable regeneration:** a second run writes nothing; golden files match byte for byte (and equal the in-repo sample output); all generated TS passes `prettier.check`.
- **No writes outside the allowlist:** an output root in a read-only path raises `WriteDeniedError` and nothing is written. The schema rejects output roots overlapping source/read-only paths (`.`, `docs`, `docs/generated`, `server.mjs`).
- **No silent changes to assertions:** a test asserts one `expect*` per structured assertion for every READY case; manual steps/checks and non-READY cases refuse to generate.
- **Not required by the gate, run anyway:** the 19 generated tests pass against the real sample app (Chrome channel). Proving they *fail* on a defect is P6-T05.

## Defects found and fixed

1. Validation caught generated code that did not compile (`countBefore1` was scoped to the steps block). Fixed and covered by a test.
2. The write allowlist always contained `testOutputRoot`, so a misconfigured output root could make source or docs writable. The schema now rejects overlaps (my own test expectation for `src/tests` was wrong; that path does not overlap).
3. Test isolation: tests that copied `examples/sample-app` picked up locally generated plans and specs. A shared clean-copy helper (`tests/helpers/sample-app.ts`) fixes this.
4. A gate chain stopped at a lint error without running later checks; replaced by `scripts/quality-gate.mjs`, which always runs every check.

## Security checks

No credentials in generated code (asserted); demo passwords exist only in the sample fixture, tests and the sample-suite script, passed via environment. Session data is not persisted in P4. Evidence redacted (`<HOME>`). Staged files scanned before commit and push.

## Remaining risks

- The generated suite needs `@playwright/test` in the target project and a browser. Here the installed Chrome channel was used; Chromium download/CI is P9.
- Text assertions outside table rows are page-level (exact text), which is weaker when the same status word appears for other records.
- Symlink test still unexecuted on Windows (1 skipped).
- Skills not yet invoked inside Claude Code by the owner (planned in P7).
