## Implementation summary

- **T01 Evidence collector** (`src/orchestrator/run.ts`): per phase, a Playwright JSON report, a Playwright HTML report (`html-<phase>/`) and its own output dir (`test-results-<phase>/`) with traces (retain-on-failure) and screenshots (only-on-failure). Run metadata: QA Agent/Node/Playwright version, platform, browser, build ID (`QA_AGENT_BUILD_ID` or target git HEAD), environment. No environment dump.
- **T02 Normalisation** (`src/reporting/normalize.ts`): one result per plan case, `PASS / FAIL / SKIPPED / BLOCKED / NOT_RUN`, with flaky flag, attempts, duration, browser, phase, worker, build ID, requirement refs, project-relative attachments and session events. `QA_AGENT_BLOCKED` maps to BLOCKED; interrupted or cut-off-by-global-timeout maps to NOT_RUN; non-READY plan cases carry their plan reason. ANSI codes are stripped and `QA_AGENT_ACCOUNT_*_PASSWORD` values masked.
- **T03 Failure analysis**: deterministic rules (`src/reporting/analyze.ts`) yield a classification (`probable_app_bug / test_automation_issue / environment_issue / insufficient_evidence`), a confidence, a rationale and evidence (requirement line, error, spec location, trace/screenshot paths); dependent cases of a failed producer are flagged. The AI part is the plugin agent `agents/failure-analyzer.md`, **read-only** (Read, Grep, Glob — contract-tested). Its JSON is saved by the skill as `ai-analysis.json` and validated by `report`: unknown or non-failing cases are rejected. It is shown next to the rules and never changes a verdict.
- **T04 Coverage** (`src/reporting/coverage.ts`): requirement → cases → executions with verdicts (passing, failing, blocked, not-run, needs-review, no-cases). Counts are kept apart: generated, ready, executed (skipped is not executed), passed, failed, blocked, skipped, not run, flaky.
- **T05** `qa-agent report` (results.json, summary.md with the executive summary, self-contained report.html) and `qa-agent full-test [--offline] [--resume]`: discover → plan → generate (+validate) → run → report, with state in `.qa-agent/full-test-state.json`. Resume skips finished stages whose input hash is unchanged; a failing stage stops the run and is retried next time. The `report` and `full-test` skills are implemented; the vertical slice now includes the report stage.
- **T06** README rewritten as a newcomer guide, plus `docs/CONFIG_GUIDE.md`, `docs/WALKTHROUGH.md`, an updated `docs/PLUGIN.md`, and `scripts/smoke/claude-fulltest-smoke.mjs` (in-Claude MVP smoke).

## Defects found and fixed in P7

1. The in-Claude run skipped the AI analysis because my full-test skill called it "optional". Both skills now make it an explicit required step.
2. **Credential echo:** in run 1, Claude printed the `QA_AGENT_ACCOUNT_*_PASSWORD` values during its precondition check (demo values only). Fixes: the redactor masks password values; run-1 evidence was re-redacted; the skills prescribe a `set`/`MISSING`-only check and forbid printing values. Hook-level enforcement is planned for P8 (threat model).
3. Coverage counted SKIPPED as executed, contrary to §8.3. Fixed and tested.
4. Playwright 1.63 reports a test cut off by `--global-timeout` as `skipped`, which made it look deliberately skipped. The normaliser now maps it to NOT_RUN when the run reports a global timeout and the test has no skip annotation.
5. The cancelled-run test depended on timing and failed under the full parallel suite. It was replaced by a deterministic probe spec.
6. Lint error in a new test, found by the clean-environment reproduction. API status messages now show the concrete path instead of `{{subject.id}}`; error excerpts in evidence keep the "Received" line.

## Security checks

The evidence is redacted (home, user name, demo password values) and scanned. Traces/screenshots stay in gitignored `qa-artifacts/`; reports warn that they may contain session data. The failure-analyzer agent has no write or shell tools.

## Remaining risks

- Claude's behaviour inside skills depends on wording. Run 1 skipped a step and echoed credentials; enforcement by hooks belongs to P8.
- Traces of failed tests can contain typed passwords (login steps); they are not redacted.
- `smoke:mcp` showed one cold-start navigate timeout right after `npm ci`.
- The plugin runs from source (Node type stripping) and needs `npm ci` in the plugin folder; packaging is P9.
- Verified on Windows with Claude Code 2.1.71 and the installed Chrome only.
- Symlink test skipped on Windows.
