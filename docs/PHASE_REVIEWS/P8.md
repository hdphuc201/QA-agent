## Implementation summary

- **T01 Threat model** (`docs/THREAT_MODEL.md`, version 2): assets, trust boundaries, threats T1–T11 with controls and the tests that prove them.
- **T02 Execution-layer policies:**
  - **Route guard.** In the generated runtime, every role context aborts requests to origins outside `allowedOrigins` and reports them as `qa-blocked`.
  - **Production refusal.** `run`, live `discover` and `full-test` refuse production without `QA_AGENT_ALLOW_PRODUCTION=1` (`src/config/policy.ts`).
  - **Destructive steps.** They make a case BLOCKED unless `policy.allowDestructive`.
  - **Artifact scrubber** (`src/evidence/scrub.ts`, `src/evidence/zip.ts`). After every run phase it rewrites trace zips, nested zips, the HTML report's embedded base64 zip and text artifacts. It masks raw, URL-encoded, form-encoded and JSON-escaped credential values; counts go into `run.json`.
- **T03 Second target app** `examples/helpdesk-app`. It differs from the first app in:
  - routing (Express-style), routes (`/signin`, `/tickets/:id`), labels (Email/Passphrase, "Log in");
  - roles (customer/agent/auditor), fields (Subject/Severity/Resolution) and output folder (`tests/qa`).

  The live full pipeline passed 17/17 on the first run after two engine fixes.
- **T04 Cross-browser:**
  - **Config.** `browsers` (chromium/firefox/webkit), one Playwright project each.
  - **Normalisation.** Worst-browser normalisation with `byBrowser`, shown in Markdown and HTML.
  - **Sessions.** Session files are per engine. Validation expects tests × browsers.
- **T05 Benchmark** (`npm run bench`). Covers stage times, regression runs at 1 vs 2 workers, flakiness, engine RSS, sampled system memory, and token cost from the redacted in-Claude transcripts.
- **T06 Credential guard hook** (`hooks/hooks.json` → `hooks/guard-credentials.mjs`). A PreToolUse hook on Bash/PowerShell. It is verified against the installed Claude Code 2.1.71. Owner-terminal smoke: `npm run smoke:claude-hook`.
- **T07** Regression gate, security review (below), README/CONFIG_GUIDE/PLUGIN docs.

## Defects found and fixed in P8

1. **Passwords in traces and HTML reports.** Playwright records `fill` values. Even passing runs had 4–17 password occurrences in the embedded report data. Now they are scrubbed after each phase; live-tested.
2. **App-specific assumption in the planner:** "appears on `/p`" always checked `data.title`. The helpdesk app has no Title field, so every ticket case became NEEDS_REVIEW/BLOCKED. It now checks the record's first generated value (unit-tested).
3. **Duplicate blocker messages** (the same dependency blocker 4×). They are deduplicated.
4. **Multi-browser results overwrote each other:** the last browser won, so a Firefox FAIL could be hidden by a WebKit PASS. Worst-browser aggregation is unit-tested.
5. **Generate-time validation** expected one listed test per case. It now expects one per case and browser.
6. **Resource contention in the gate:** with the new live files, 13 test files ran at once. The first test of a worker timed out on `page.goto` (P5/P7 tests, reproducible only under the full parallel suite). Integration files now run one at a time; no retries or timeouts were changed.
7. **A heredoc collapsed `\\`** in the test helper's path regex (Windows paths no longer matched). Caught by lint and fixed with the Edit tool.

## Security review

- **Credentials**:
  - **Values:** never in config (rejected), command lines (hook), outputs (masked) or artifacts (scrubbed).
  - **Session files:** per engine, purged after runs.
  - **Helpdesk demo accounts:** fixture data, documented in the app header.
- **Network:** generated tests are confined to `allowedOrigins` at runtime. Exploration keeps its own two layers (P2).
- **Environment:**
  - Production is refused without explicit owner approval.
  - The reset endpoint is refused for production (schema).
  - Destructive steps are BLOCKED by default.
- **Repository:** the commit scan found no home paths, user names, account emails, tokens or private keys. `.serena/` stays untracked: it was found staged by something outside this session and was unstaged. Generated example outputs (`examples/**/tests/qa/`) are gitignored.
- **Least privilege:** the failure-analyzer agent is still read-only. The hook only denies; it never edits or approves.

## Remaining risks

- **Hook not yet proven in a live session.** It is verified by the protocol in the CLI source and by unit tests. The in-session proof needs the owner-terminal smoke (`npm run smoke:claude-hook`, about 0.05–0.3 USD).
- **The hook covers shell tools only.** Reading a credential file with Read is not intercepted; credentials are not expected in files.
- **Screenshots and videos** can show typed values only as masked password fields; other on-screen data is not scrubbed.
- **One cold-start Firefox failure** (1 of 204 browser-case executions); the error text was not captured. The assertion message now includes the error, so a recurrence will be diagnosable.
- **Memory figures are coarse.** System memory is sampled (browsers included), not per process.
- **Worker cap.** The scheduler still caps parallel workers at 2 (ADR 0006); the benchmark shows a 19–21 % gain from 1 to 2 workers, and higher values are untested.
