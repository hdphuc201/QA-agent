## Implementation summary

- **T01** Roles reference accounts by `accountKey`; credentials come only from `QA_AGENT_ACCOUNT_<KEY>_*` at run time and are never stored. The opt-in session cache (`session.cache`) writes the storageState atomically to gitignored `qa-artifacts/auth/`. A cached session is reused only if fresh and still accepted at `verifyPath`, otherwise the role signs in again (controlled refresh). Cached sessions are purged before and after runs.
- **T02** Session manager in the generated runtime: a BrowserContext per role, additional tabs per role context, an anonymous context, and teardown in `finally`. A role whose sign-in is under test always gets a fresh context (planner marks inserted logins `implicit`).
- **T03** `src/orchestrator/scheduler.ts`: dependency levels, isolation verdicts and worker decisions, with cycles refused. `src/orchestrator/run.ts` + `qa-agent run`: two phases (parallel isolated cases, then serial shared-state cases) using the target's Playwright, run records under `qa-artifacts/runs/<runId>/`. Observable-state sync uses Playwright auto-waiting and `expect.poll` (no sleeps), explicit action/navigation/expect timeouts, and retries 0 by default.
- **T04** Worker budget: default `workers.writeHeavy` (1). Isolated cases go to `min(workers.max, 2)` after an independence proof; `@serial` cases (e.g. REQ-002, which counts a shared list) run with 1 worker. All data is unique per test; the global reset runs before each run.
- **T05** Two-role workflow (requester creates → approver approves → requester sees "Approved"), forbidden actions for requester/viewer (UI + API 403) and session isolation, all exercised for real.
- **T06** Teardown and leak checks, an unexpectedly closed page/context, a cancelled run (global timeout) and a hard kill, each followed by a clean run.
- The `run` skill now calls the engine. ADR 0006 records the decisions.

## Test evidence (gate criteria)

- **Two roles with independent contexts:** S1 asserts different session cookies for requester and approver, a second requester tab sharing the requester session, the approver page showing Bob, and the anonymous API getting 401.
- **No session leak between roles:** S1 checks the cookies; S2/S5 assert `browser.contexts().length === 0` after a normal and after a broken test.
- **Action verified by state or API per requirement:** APP-001 checks the "Approved" status seen by both roles. APP-003 checks the absent button and HTTP 403 for requester and viewer; the request stays "Pending".
- **Test data cleanup:** the reset endpoint runs in globalSetup; unique per-test data; cached sessions purged (including after a cancelled run, by the next run).
- **No shared-account collision in parallel:** 3 consecutive two-worker runs passed (18 isolated cases); the one shared-state case is serialised.

## Defects found and fixed

1. With the session cache, "Sign in with valid credentials" reused a session instead of signing in. The test was still green but no longer tested sign-in. Fixed with `implicit` logins and fresh contexts; verified by per-test session events.
2. Playwright skips the teardown purge for an interrupted run, so session files remained. The purge now also runs in globalSetup and in the engine.
3. Validation `--list` overwrote the JSON report of real runs; it now uses the list reporter only.
4. The engine also ran custom specs in the output folder; it now runs only the plan's generated spec files.
5. Test harness bugs: `spawnSync` deadlocked the in-process sample app (a cancelled-run test had passed for the wrong reason); fixed with async spawn plus an assertion that the run really started.

## Security checks

Session files (cookies) only under gitignored `qa-artifacts/auth/`, purged; never committed. No credentials in code, plans, specs or evidence except documented demo fixture values. Runs are refused for base URLs outside `allowedOrigins`.

## Remaining risks

- After a hard kill, session files remain until the next run (no process can clean up). The `maxAgeMinutes` window limits reuse.
- Session verification assumes an unauthenticated `verifyPath` redirects to the login page; apps that do not behave this way should keep `session.cache` off (the default).
- Orphaned browser processes after a hard kill are not checked automatically.
- The parallel cap of 2 is a policy; higher worker counts are unproven.
- Symlink test still skipped on Windows; skills not yet run inside Claude Code by the owner (P7).
