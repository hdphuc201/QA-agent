## Security checks

- No secrets/credentials in changed files or transcripts (`apiKeySource: none`). The `qa-smoke-*` values are random public demo tokens.
- `.mcp.json` has no `env`; no unrestricted file access, no sandbox disable, isolated in-memory profile, localhost-only origins, output confined to gitignored `qa-artifacts/`.
- Nested-session guard respected (no `CLAUDECODE` bypass). No production URL contacted; the blocked `example.com` request never left the browser.
- **Owner decision before commit:** the stream-json transcripts in `evidence/P1/*.jsonl` list the names of the owner's other plugins/MCP servers (other plugins, MCP servers and connectors) and local Windows paths with the user name. Not secrets, but environment metadata; keep or redact before pushing to a public remote.

## Remaining risks

- Verified only on Claude Code **2.1.71**. Current docs describe newer versions (e.g. `displayName`, MCP checks in `plugin validate` from v2.1.281); behaviour on newer CLIs is not tested.
- Interactive mode (`claude --plugin-dir .` then typing `/qa-agent:discover`) was not exercised; loading was verified with `-p --plugin-dir`, which uses the same plugin loader.
- The origin allowlist is a guardrail, not a security boundary. Powerful tools (`browser_evaluate`, `browser_run_code_unsafe`, `browser_file_upload`) are exposed but not pre-approved; narrowing is P2/P8 work.
- The browser depends on the default channel (installed Chrome here). Machines without Chrome are untested.
- The first MCP start needs registry access (`npx` download of the pinned version).
- The owner's global `SessionStart` hook runs in plugin sessions and keeps a lock on a directory it creates in the session cwd; outside QA Agent's control.
- `smoke:claude` costs API credits and needs an owner terminal, so it cannot run in unattended CI yet (P9).
- The smoke scripts were reformatted by Prettier after run #3 (formatting only; logic unchanged). Skill files are byte-identical to the run #3 version.
- Linux/macOS not executed.
