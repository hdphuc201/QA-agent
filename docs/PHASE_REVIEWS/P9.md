## Implementation summary

- **T01 CI** (`.github/workflows/ci.yml`). Runs on GitHub-hosted runners; the repository is public and no secrets are used.
  - The `checks` job runs on Ubuntu and Windows: typecheck, lint, format, build, bundle freshness, unit + contract tests (JUnit), `claude plugin validate` with Claude Code 2.1.71, and `progress check`.
- **T02 Integration job** (Linux):
  - a Playwright browser cache, then `playwright install --with-deps chromium firefox webkit` and an MCP warm-up;
  - serial live integration tests and the vertical slice;
  - a JUnit failure summary in the job summary (`scripts/ci/junit-summary.mjs`) and artifacts kept 14 days.
- **T03 Packaging.**
  - **Engine:** a self-contained bundle `bin/qa-agent.mjs` (esbuild, zod inlined); the skills call it. The plugin version comes from the manifest. Strict type-check and Prettier come from the target project or the plugin checkout; a missing TypeScript is reported as "not run".
  - **Distribution:** marketplace manifest, version 1.0.0, `CHANGELOG.md`.
  - **Install test:** `scripts/smoke/install-smoke.mjs` installs from a local clone or from GitHub into an isolated `CLAUDE_CONFIG_DIR`, then runs the installed engine.
- **T04** [`docs/TUTORIAL.md`](../TUTORIAL.md): install from the GitHub marketplace and set up two different target projects (approvals, helpdesk). Covers configs, credentials, the Claude and CLI flows, cross-browser, your own project, and troubleshooting. The README links it.
- **T05** `scripts/release-dry-run.mjs` checks:
  - a clean tree and version agreement;
  - bundle freshness and plugin validation;
  - a secret and personal-path scan of all tracked files;
  - dependency licenses, and records the archive digest.

  Nothing is tagged, pushed or published. [`docs/RELEASE.md`](../RELEASE.md) holds the release steps, the compatibility matrix (verified only) and the licensing/security checklists.
- **T06** Final readiness review (below), v1.0 gate, `docs/FINAL_PROJECT_REPORT.md`.

## Defects found and fixed in P9

1. **An installed plugin could not run its engine.** The skills ran TypeScript sources that import `zod`, and validation used the plugin's own TypeScript; an install has no `node_modules`. Fixed with the committed bundle and target-first tool resolution (ADR 0008).
2. **The version was read from `../../package.json`** relative to the module, which is wrong once bundled. It now comes from the plugin manifest, also used for the MCP client info (was hardcoded `0.1.0`).
3. **`full-test` exited 0 when no test had run** (0/0 passed, 17 not run): success was decided by the text "failed 0, blocked 0". It now requires every READY case to reach PASS or a deliberate skip (`fullTestSucceeded`, unit-tested).
4. **A GitHub clone failed on Windows:** two committed Playwright failure folders made paths longer than 260 characters. The folders were renamed (mapping in their `NAMES.md`), and a contract test keeps every tracked path ≤ 120 characters.
5. **Reporter flags placed after the file globs** were taken as file patterns by `node --test` and crashed it. CI now uses dedicated `test:*:ci` scripts.
6. **The dry-run key scan flagged a header-only fixture** in a redaction test. A real key must have a body; the fixture stays.
7. **In-process app plus `spawnSync`.** The first install smoke started the example app in its own process, and the blocked event loop failed the test-data reset. The app now runs as a child process.

## Final readiness review

- All phase gates P0–P8 passed. P9 passes with this review; see the progress summary.
- **Security** (threat model T1–T11):
  - controls are implemented and tested;
  - the commit scans and the dry-run scan are clean;
  - CI has `contents: read` and no secrets;
  - CI artifacts are public (public repository) but hold only fixture data, and passwords are scrubbed.
- **Safety rules kept:**
  - nothing was tagged, published or deployed;
  - no production target was used, and no paid service was enabled (public-repository Actions);
  - `.serena/` and `.code-review-graph/` were never committed;
  - the nested-Claude guard was never bypassed;
  - owner-terminal smokes are provided instead.
- **Flakiness under load** (recorded, not retried):
  - 1 cold-start Firefox failure (P8);
  - 1 failure of the full-test integration file in 3 runs during P9, not reproduced in 2 further runs and later CI. Its output was not captured.
