## Implementation summary

- **T01** `src/config/project-config.schema.ts` (Zod 4.6.5; JSON Schema generated): `projectId`, `framework`, `environment`, `baseURL`, `allowedOrigins` (baseURL origin required), `docsPaths`/`sourcePaths`/`readOnlyPaths` (relative, no `..`), `testOutputRoot`, `roles` (`accountKey` only), `workers`, `exploration` (pages, timeout, retries, login recipe). Credential-like keys are rejected.
- **T02** `src/discovery/source-reader.ts`: reads configured docs/source only. It skips `.env*`, keys, credential/storage-state files, binaries, dependency/build/test-artifact folders and paths outside the project; it enforces size/count/total limits and redacts secret-looking values.
- **T03** `src/discovery/project-map.ts`: static map of routes (Express, node:http comparisons, regex routes, Next.js file routes, API references in docs), forms with labelled fields, links/buttons and role hints. Each item has `file:line` sources, provenance and confidence.
- **T04** `src/discovery/{mcp-client,snapshot,url-guard,explorer}.ts`: live exploration through the plugin's Playwright MCP server, with `--allowed-origins` taken from the project. The tool policy allows navigate/snapshot/close, plus fill/click only for the login recipe. URLs are checked before and after navigation; state-changing-looking GETs are skipped; timeouts, retries and `maxPages` apply; passwords are masked everywhere. Credentials come from `QA_AGENT_ACCOUNT_<KEY>_*` (`src/sessions/accounts.ts`).
- **T05** `src/discovery/discover.ts` + `src/cli.ts discover`: writes `.qa-agent/discovery/project-map.json` (validated contract) and `observations.json`. Provenance is `observed` / `source-derived` / `hypothesized`; `observedIn` links lead from routes/UI/forms/roles to observation IDs. Writes go through `src/config/write-guard.ts`.
- **Sample target app** `examples/sample-app/` (ADR 0004): approval workflow with requester/approver/viewer, requirements doc with IDs, test-mode reset, opt-in intentional defect, `.qa-agent/config.json`.
- The `discover` skill now calls the engine (contract test enforces implemented vs skeleton status).

## Test evidence (gate criteria)

- **Valid manifest from the demo app:** `tests/integration/discover-live.test.ts` runs `qa-agent discover` against a temp copy of the sample app with real Playwright MCP. It gets exit 0, `project-map.json` parses with `ProjectMapFileSchema`, the requester signs in, and 4+ pages are observed, including the dynamic `/requests/REQ-1` reached by following a link.
- **Traceability:** `GET /requests/new` has `server.mjs` sources and `observedIn` IDs that resolve to pages in `observations.json`. The `New request` link resolves to an observed element with the same role and name.
- **URLs outside the allowlist are refused:** the QA Agent guard blocks `https://example.com/`, `file:///…` and `/logout` before the browser sees them. MCP itself, started with the project allowlist, returns `ERR_BLOCKED_BY_CLIENT` for a direct call. Unit tests also cover redirect escape, schemes and embedded credentials.
- **No secrets:** the source reader skips secret files and redacts values (unit tests). The sign-in password never appears in the outputs or CLI log (asserted live).
- **No unauthorized mutation:** after exploration the app still holds exactly the seed (`REQ-1 Pending`). Only navigate/snapshot plus the login fill/click are called. No `.playwright-mcp/` dir appears in the project.
- **Flake found and fixed:** repeated runs exposed a transient MCP navigate error after a blocked navigation (1 of 5). The explorer now retries non-blocking navigation errors; 8/8 runs passed afterwards, and 3/3 more were recorded as evidence.
- Regression: all P0/P1 tests still pass (progress CLI 25, contract 11, paths 11, redaction 5).

## Security checks

Credentials only via environment variables and masked in outputs. Config rejects credential-like keys. Writes limited to the allowlist and outside `readOnlyPaths`. Exploration is local (127.0.0.1) only. No production URL was contacted.

## Remaining risks

- Symlink-escape protection is implemented but **not executed** here (Windows without Developer Mode); 1 skipped test.
- Static extraction is heuristic; frameworks beyond Express, node:http and Next.js file routes give partial maps (live observation compensates).
- The aria snapshot of password fields was not shown to contain values, but masking relies on knowing the secret value; unknown sensitive page content (e.g. PII) is stored as observed.
- The `discover` skill inside Claude Code (`${CLAUDE_PLUGIN_ROOT}` substitution on 2.1.71, Bash permission prompt) has **not** been run in an owner terminal yet; the engine was verified directly. Planned for the in-Claude smoke of the full pipeline (P7).
- Running from source needs Node ≥ 22.12 (type stripping) and the plugin's `node_modules` (zod); packaging is P9.
