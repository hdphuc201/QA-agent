# QA Agent — threat model

- Version: 2 (P8-T01 2026-10-19; controls implemented and tested in P8-T02..T06, see ADR 0007)
- Scope: the QA Agent plugin (skills, agent, Playwright MCP config), the engine (`src/`), and what it writes into target projects.
- Not in scope: the security of the target application itself (that is what QA Agent tests), Claude Code and Playwright internals.

## Assets

| Asset                          | Where it exists                                                               | Why it matters                                      |
| ------------------------------ | ----------------------------------------------------------------------------- | --------------------------------------------------- |
| Role credentials               | user environment `QA_AGENT_ACCOUNT_<KEY>_*`, typed into login forms           | access to the target system as a real role          |
| Session cookies / storageState | browser contexts; `qa-artifacts/auth/` when `session.cache` is on             | equivalent to credentials until they expire         |
| Test artifacts                 | `qa-artifacts/runs/*`: traces, screenshots, error contexts, HTML/JSON reports | can contain page data, typed values, network bodies |
| Target source and documents    | `sourcePaths`, `docsPaths` (read-only)                                        | confidential code/docs; must not be modified        |
| Target data                    | the app under test                                                            | tests create data; resets delete data               |
| The developer machine          | files outside the project                                                     | must not be read or written                         |

## Actors and trust

- **Owner / user** (trusted): chooses the target, provides credentials, runs skills.
- **Claude** (semi-trusted executor): follows skill instructions, but can deviate. P7 showed both skipping an instructed step and echoing credentials.
- **Target web content and documents** (untrusted input): pages, requirement files and source comments can contain text that tries to steer an AI ("prompt injection").
- **Playwright MCP server** (trusted tool, not a security boundary, per upstream).

## Residual risks (accepted for now)

- A **hard kill** of a run leaves cached session files until the next run, and leaves unscrubbed artifacts of the interrupted phase. Session files exist only with `session.cache` on; the scrubber runs again at the start of the next run.
- Screenshots are images and are not scrubbed. Password inputs render masked, but other sensitive page content can appear. Keep `qa-artifacts/` inside the team.
- Values that are not registered as secrets (e.g. PII on pages) are not scrubbed.
- Hooks and skills reduce, but cannot eliminate, an AI deviating from instructions; the deterministic engine does not depend on the AI for safety-relevant decisions.
- Playwright MCP exposes powerful tools (`browser_run_code_unsafe`, …). Discovery never calls them, but a user could invoke them interactively.
